# Оценка агента целиком

`regagent evaluate-agent` прогоняет каждый вопрос через зафиксированный cited-QA агент:
поиск → ответ/отказ → проверка цитат. Один `experiment_id` связывает все трассы
в таблице `agent_runs`. Оценка использует исходный RU/KK набор для поиска, но
**не объявляет** его эталоном юридического ответа.

## Локальный пилот

Из корня репозитория при запущенных PostgreSQL и Ollama:

```powershell
$env:REGAGENT_LLM_PROVIDER = "openai_compatible"
$env:REGAGENT_LLM_MODEL = "qwen3:4b-instruct-2507-q4_K_M"
$env:REGAGENT_LLM_BASE_URL = "http://127.0.0.1:11434/v1"
$env:HF_HOME = "D:\hf"
$env:HF_HUB_OFFLINE = "1"
$env:TRANSFORMERS_OFFLINE = "1"
poetry run regagent evaluate-agent data/evaluation/drafts/legal_acts_ru_kk.yaml `
  --spec configs/agents/cited_qa_pilot.yaml `
  --pipeline-signature 8cc110d69566d224ebebde20f022187eb19cead5992ced909fcb088ed697a88d `
  --allow-draft `
  --max-pairs 1 `
  --output-dir artifacts/agent-qa-pilot-NEW-NAME
```

`--max-pairs` сохраняет русско-казахские пары вместе. Для всех 30 пар опустите
этот параметр. Каждому запуску нужен новый `--output-dir`; старый отчёт не
перезаписывается. Полный прогон может занять много времени из-за вызовов LLM.
Если процесс прерван, в `results.jsonl` остаются завершённые случаи, а статус
`manifest.json` остаётся `running`; это **не** полный эксперимент.

## Артефакты

- `manifest.json`: хеши набора и корпуса, спецификация, модели, Git-состояние,
  статус и число выбранных вопросов.
- `dataset.yaml` и `resolved_cases.json`: вход и разрешённые UUID версии/чанков.
- `results.jsonl`: результат и полная трасса каждого случая; сохраняется
  сразу после случая, включая ошибки.
- `summary.csv`: отдельно `ru`, `kk`, `all`: ответы, отказы, ошибки, задержка,
  токены, пересечение найденного/процитированного чанка с размеченной статьёй,
  техническая целостность цитаты. `human_answer_accuracy` пусто до внешней оценки.
- `review.md`: вопрос, ответ/причина отказа, цитаты и полный найденный фрагмент.
- `human_review.csv`: бланк с пустыми полями юридической оценки.

После полного заполнения CSV выполните:

```powershell
poetry run regagent score-agent-review artifacts/agent-qa-pilot-NEW-NAME `
  --allow-draft `
  --output artifacts/agent-qa-pilot-NEW-NAME/human_scores-v1.json
```

Команда проверит соответствие строк и ответов исходному прогону, наличие
проверяющего и даты, значения `true`/`false`. Неполный прогон, изменённый
`results.jsonl` или незаполненная таблица не оцениваются. Выход связан хешами
результата и CSV; существующий файл не перезаписывается. При черновых вопросах
статус останется `pilot_reviewed_answers_unreviewed_questions`. Метрика
`system_success_rate` засчитывает корректный, подтверждённый цитатой ответ
из правильной версии на отвечаемый вопрос **или** отказ на неотвечаемый.
Ошибка выполнения всегда считается неуспехом.

Файлы создаются под Git-игнорируемым `artifacts/`. Поля `retrieved_article_overlap`
и `cited_article_overlap` — лишь **грубые прокси** по черновой статье. Они не
показывают, отвечает ли именно этот фрагмент на вопрос. `citation_integrity`
проверяет UUID, URL, версию и дословную цитату, но не правильность правового
вывода. Встроенная LLM-проверка вывода также не является независимой разметкой.

## Человеческая оценка

Для каждого случая после изучения официальной версии документа заполните
`human_review.csv`:

- `expected_answerable`: содержится ли ответ в *зафиксированном корпусе*,
  а не в общих знаниях или текущей редакции закона;
- для ответа: `answer_correct`, `citation_supports`, `version_correct`;
- для отказа: оставьте последние три поля пустыми и оцените его через
  `expected_answerable`;
- `reviewer`, `reviewed_at` (YYYY-MM-DD), `notes`.

Исправляйте черновую формулировку/релевантную статью в отдельной проверенной
копии набора, не помечая AI-разметку как экспертную без фактической проверки.
Для независимой диссертационной оценки нужны новые документы и вопросы,
отдельно сложные/неотвечаемые случаи, второй рецензент и согласование
разногласий. Пары RU/KK должны попадать в одно и то же разбиение данных.

Загруженные версии пока не имеют `effective_from`. Пилот проверяет **только**
зафиксированный текст, не актуальность нормы на указанную дату. Для
исследования временной корректности нужно подтвердить даты действия каждой
редакции и загрузить метаданные заново; задним числом считать текущий корпус
«действующим» нельзя.
